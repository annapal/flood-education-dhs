
This repo contains code for the following paper
- Palmer, A. Y., et al. (Under Review). *Flood exposure and the likelihood of receiving formal education in 34 countries*.

## Code organisation
- `_run.R` is the main script that runs the entire analysis. *This is the only script that needs to be run by the user*.
- `packages.R` loads all required packages
- The directory `R` contains the functions that support the `_run.R` file
- `R/analysis_list.R` lists every model specification; `run_models()` fits them all and writes `results/results.csv`
- The directory `data` holds the country list (`countries.csv`) and an example of the expected DHS file paths (`files.csv`); everything else it contains is downloaded by the user or generated by the pipeline, and is not tracked in git
- `utils` contains a short script to help unzip the DHS files
- `scripts` contains sbatch files for running the slower steps on a computing cluster

## Main outputs
- The directory `figures` contains all the figures included in the paper
- The directory `results` contains all the results in csv and xlsx files

## Instructions for running the code
DHS, flood, and population files are not uploaded, and must be directly downloaded from the source. Large source files are read from the path set by `dat_path` at the top of `_run.R` (`~/data` by default); reference files live in `data/` inside the repo.

1. To download DHS files, access must be requested at https://dhsprogram.com/. Datasets should be downloaded via the download manager, in Stata file format, for the 34 countries listed in `data/countries.csv`.
Household member recode (PR) datasets should be saved under `~/data/dhs/`, women's recode (IR) under `~/data/dhs-ir/`, and men's recode (MR) under `~/data/dhs-mr/`. DHS GPS data should be saved in `~/data/geocodes/`.
The script `utils/unzip_files.R` may be useful in bulk unzipping all files. The file `data/files.csv` should give you an idea of what the file pathways should look like.
2. Flood extent data can be downloaded from the Global Flood Database (https://global-flood-database.cloudtostreet.ai/), version 1.4. Each event folder should be saved in `~/data/gfd_v1_4/`, keeping the GeoTIFFs and the `<dfo_id>_properties.json` file that accompanies each event.
3. Flood characteristics (severity, deaths, displacement) come from the Dartmouth Flood Observatory archive (https://floodobservatory.colorado.edu/), saved as `data/FloodArchive.xlsx`.
4. Population data should be saved in `data/population/`. Two files come from UN World Population Prospects 2024 (https://population.un.org/wpp/): `WPP2024_Demographic_Indicators_Medium.csv` and `WPP2024_Population1JanuaryBySingleAgeSex_Medium_1950-2023.csv`. The global coresidence dataset is used for household size, downloaded from https://zenodo.org/records/12721630 and saved as `12721630/A0_CORESIDENCE_NATIONAL_DATASET_2024.csv`. The World Bank income classification used in the extrapolation (`CLASS_2025_10_07.xlsx`) is already included in the repo.
5. For the extrapolation only, WorldPop 1km age-sex rasters (https://www.worldpop.org/) should be saved in `~/data/worldpop/`, named `global_{sex}_5_{year}_1km.tif`.
6. Once these steps have been completed, run `_run.R` to reproduce the analysis.

Two steps in `_run.R` are commented out because they take a long time, but must each be run once before the rest of the pipeline: `process_flood_tifs(dat_path)` links the flood data to DHS clusters, and `make_flood_raster(dat_path)` builds the raster used in Figure 1.
